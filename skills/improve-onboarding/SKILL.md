# Improve onboarding

Help a new user experience the product's value with the minimum necessary effort and enough context to make informed choices. Signup completion alone is not activation.

## Define the useful outcome

Establish the intended audience, acquisition promise, first useful result and prerequisites. Inspect existing product documentation, journey and available data before inventing an activation event. Use a provisional definition if needed and label it as such.

Separate users with different needs when it changes the journey: new versus returning, invited versus self-serve, or starting from an example versus a blank state. Do not add segmentation or personalisation steps without a purpose.

## Walk through the journey

Follow the relevant path from entry page through signup, setup and the first meaningful result. Include mobile, slow or failed requests, empty data, interrupted sessions and resuming where relevant.

- Match the acquisition promise to what the product delivers next. Avoid a tour that delays the outcome or sends people into unrelated educational content.
- Ask only for information necessary at that point. Explain consequential choices and provide sensible, reversible defaults without silently choosing a user's interests.
- Reveal complexity when it becomes useful. Give help where the user needs it rather than adding an introductory step for every feature.
- Show progress through actual work, not artificial completion badges. Make the next action clear and loading or error states recoverable.
- Explain pricing, free-access limits, permissions and what happens next at the appropriate decision point. Avoid surprise charges, misleading scarcity and cancellation obstruction.
- Check authentication redirects, profile provisioning, saved choices and access gates where they affect the path. A new user should not be treated as expired simply because setup is incomplete.

Do not remove productive effort that constitutes the product's value. For example, explaining an idea may be the learning activity itself; making the answer effortless could weaken the result.

## Use evidence carefully

Use authorised funnels, recordings, interviews or support reports when supplied. Define the time window, cohort, event denominators and device or channel differences. Distinguish observed abandonment from its suspected cause; a click rate alone does not explain user intent.

If evidence is limited, explain the heuristic finding and propose a small way to test it. Do not claim a conversion uplift before observing one.

## Recommend and verify

Describe the concrete obstacle, proposed change and why it should help the first useful outcome. Prioritise changes the user can act on. Include the activation measure and downstream check, such as repeat use or successful task completion, plus relevant guardrails.

For implementation, preserve existing account data and resume behaviour. Test the affected path and its important failure state with authorised or synthetic accounts. Separate review findings, implemented changes and measured results.
